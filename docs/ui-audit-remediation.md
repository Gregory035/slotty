Исправления выполнены без редизайна, миграций БД и расширения прав ролей. Проверки ниже проводились локально до отдельной публикации.

## Проверки

`npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.

Добавлены unit-регрессии:

- nullable/empty/omitted email, очистка публичного адреса и его валидация;
- даты компании около полуночи, недельные границы, DST и крайние UTC-offset;
- безопасные пользовательские ошибки;
- вложенные блокировки прокрутки и повторная очистка эффекта.

Финальный результат: typecheck, lint, production build, 153 unit-теста (109 API + 44 web), 3 integration-теста и 8 существующих браузерных E2E прошли.

Браузерные доказательства и логи: `output/playwright/fixes-2026-10-28/`. Основной `regression.mjs`: 24 проверки в Chromium/WebKit, все прошли. Отдельный `visual.mjs`: 56 измерений/проверок размеров, контраста и состояний, все прошли. Общий диалог проверен на 11 размерах в обеих темах и движках; отсутствие переполнения privacy/public company — на всей базовой матрице. Подтверждены очистка email и пустого публичного адреса, сохранение своего графика сотрудником, одинаковые координаты календаря в трёх зонах устройства, загрузка и показ фото без pageerror, Escape/Tab/возврат фокуса и отсутствие запрещённых employee/billing-запросов.

Все сценарии используют отдельные PostgreSQL/Redis, не рабочую БД. При снятии цветовых измерений дожидались перерисовки темы; сборка файлов не выполнялась параллельно с браузерным прогоном.

Локальная сборка для проверки: API и web через один origin, `VITE_API_URL=/api`, индексирование отключено только в локальной сборке. Фото действительно загружаются и отображаются; в исходном аудите их локальному показу мешала схема с разными origin, а не потеря файла.

Первые диагностические прогоны сохранены отдельно от аудита. Ошибки самих проверок (счётчик rate limit, ожидание загрузки списка фото и перерисовки темы) не трактуются как продуктовые дефекты.

## Ограничения

WebKit — не физический iPhone/Safari/Telegram. На устройствах отдельно остаются проверка системной клавиатуры, PWA push, Telegram WebView и safe-area при системных жестах. Реальные письма, платежи и клиентские сообщения во время регрессии не отправлялись.

Публикация выполняется по отдельной команде владельца через CI и workflow Deploy production; версия релиза определяется commit SHA и проверяется после развёртывания.
