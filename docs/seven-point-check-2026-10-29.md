## После отдельной публикации

При повторной проверке конфигурации GitHub обнаружено отсутствие VITE_YM_COUNTER_ID и на уровне репозитория, и в production environment. Workflow использует vars.VITE_YM_COUNTER_ID: такие сборки получали пустой ID. Публичная переменная репозитория установлена в существующий счётчик 112790410, значение прочитано обратно. В workflow добавлена проверка положительного числового ID перед публикацией. Для изменения уже работающего сайта нужна новая сборка и отдельный деплой. Приём события самим внешним счётчиком до этого не подтверждён; созданием переменной он не считается проверенным.

Ограничение дополнительного сетевого теста: перехват ответа воспроизводится в Chromium; в WebKit тест не показывал ожидаемую ошибку после перехвата, точная причина не установлена. Поэтому сетевой сбой проверяется только в Chromium, обычная запись — в обоих движках. Проверка сбоя сети на iPhone остаётся открытой; это не подтверждённая ошибка самого приложения.

Дополнительная проверка восстановления: запросы Mini App ограничены 20 секундами. Добавлен unit-тест сетевой ошибки и браузерный сценарий: реальный API фиксирует визит, вместо успешного ответа клиент получает 503 промежуточного соединения, повторная отправка должна завершиться успехом с ровно двумя услугами исходного визита, без дублей. Перехватывается только POST, не служебный OPTIONS. Получение событий внешней Метрикой не подтверждено: production в этой сессии загружался с тайм-аутом. Отдельной публикации и проверки на физических устройствах не было.

1. С разрешением на аналитику проверить доставку просмотра и регистрации в Метрику на тестовом аккаунте, без передачи личных данных.
2. В Search Console проверить live URL трёх приоритетных страниц: `/online-zapis`, `/dlya-mastera`, `/dlya-salona`; сверить свежий статус с датой отчёта.
3. На физических устройствах выполнить запись/отмену/повтор, отказ сети во время подтверждения и возврат в Mini App. Не создавать тестовые визиты в реальных компаниях без согласования.
