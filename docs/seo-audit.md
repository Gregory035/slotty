# SEO-аудит Slotty

Дата проверки: 15 сентября 2026 года. Публичный origin этой итерации: `https://212.74.224.226.nip.io`.

## Политика маршрутов

| Группа | Маршруты | Индексация |
| --- | --- | --- |
| Маркетинг | `/`, `/online-zapis`, `/zapis-cherez-telegram` | `index,follow`, canonical, sitemap |
| Вход и регистрация | `/app`, `/app?mode=register` | `noindex,nofollow`, без canonical и аналитического pageview |
| Кабинет | `/companies/:companyId/:section` | авторизация + `noindex,nofollow`, без sitemap |
| Неизвестные URL | любые остальные | HTTP 404 + `noindex,nofollow` |

Публичной витрины компаний в текущем продукте нет. Процесс Telegram-записи не публикует данные клиентов, токены и внутренние идентификаторы в HTML или sitemap.

## Подтверждённые проблемы и исправления

| Проблема | Доказательство до исправления | Влияние | Приоритет | Статус |
| --- | --- | --- | --- | --- |
| Пустой исходный HTML | `index.html` содержал только корневой контейнер; контент появлялся после JS | Роботу требовался отдельный этап рендеринга | P0 | Исправлено: build-time prerender трёх страниц |
| SPA возвращала 200 для неизвестных URL | Nginx использовал общий fallback на `index.html` | Soft 404, расход обхода, дубли | P0 | Исправлено: отдельный `404.html` и настоящий HTTP 404 |
| Sitemap мог использовать localhost | генератор имел небезопасный fallback | Некорректные URL в индексе | P0 | Исправлено: обязательный `SEO_INDEXING_ENABLED`, строгая проверка HTTPS-origin |
| Недостоверный `lastmod` | дата сборки добавлялась как дата изменения контента | Поисковику передавался ложный сигнал | P1 | Исправлено: `lastmod` исключён |
| robots.txt блокировал приватные страницы | `Disallow` для кабинета | Робот не мог прочитать `noindex`; robots не защищает данные | P0 | Исправлено: обход разрешён, приватность обеспечивают авторизация и noindex |
| Неполные метаданные | отсутствовали canonical, OG/Twitter image и уникальные данные для отдельных намерений | Слабые/некорректные сниппеты и дубли | P1 | Исправлено для трёх публичных URL |
| JSON-LD не соответствовал маршруту при SPA-переходе | схема была статичной | На странице могла остаться схема предыдущего URL | P1 | Исправлено: единая карта и синхронизация JSON-LD |
| Возможная утечка приватного URL в аналитику | pageview отправлялся для всех SPA-маршрутов | ID компании мог попасть во внешнюю аналитику | P0 | Исправлено: pageview только для публичной карты маршрутов |
| Двойные SPA-pageview | отсутствовала дедупликация последнего URL | Искажённые показатели | P1 | Исправлено: дедупликация и единичная инициализация после согласия |
| Блокирующий Google Fonts `@import` | шрифты запрашивались из внешнего CSS | Дополнительная цепочка соединений и зависимость от третьей стороны | P1 | Исправлено: локальные WOFF2, `swap`, preload основного начертания |
| Общий стартовый CSS/JS | кабинет и лендинг собирались вместе | Лишний код на маркетинговой странице | P1 | Исправлено: приватный AppShell, React Query, Zustand и CSS кабинета загружаются лениво |

## Реализованное состояние

- Уникальные `title`, `description`, H1, canonical, Open Graph и Twitter Card для каждого публичного URL.
- PNG-превью 1200×630 создано из существующей визуальной системы Slotty.
- Главная получает `WebSite` и `SoftwareApplication`; вложенные страницы — видимые breadcrumbs и `BreadcrumbList`.
- FAQ видимый, без FAQ JSON-LD и обещаний расширенного сниппета.
- В sitemap ровно три абсолютных canonical URL без параметров и `lastmod`.
- Preview-сборка целиком `noindex` и не создаёт sitemap.
- Query-параметры не попадают в canonical.
- Nginx нормализует завершающий слеш постоянным редиректом и отдаёт `X-Robots-Tag` для кабинета и 404.

## Производительность

- основной JS: 225,8 КБ / 70,4 КБ gzip;
- весь стартовый JS: около 104 КБ gzip;
- CSS: 95,1 КБ / 17,8 КБ gzip.

После разделения публичной и приватной частей:

- стартовый публичный JS: 211,5 + 49,4 + 14,7 КБ, суммарно 88,2 КБ gzip;

## Локальная проверка результата

- Nginx-конфигурация прошла `nginx -t` в runtime-образе проекта.
- `/`, `/online-zapis`, `/zapis-cherez-telegram` возвращают 200; `/app` и маршруты компаний — 200 с `X-Robots-Tag`; неизвестный URL — 404 с `X-Robots-Tag`.
- Завершающий слеш возвращает 308 с относительным `Location`, без утечки внутреннего порта reverse proxy.
- Playwright подтвердил прямое открытие и refresh вложенного URL без hydration/console ошибок, SPA-обновление canonical/JSON-LD и CTA на регистрацию.
- На 440×956 нет горизонтального скролла; основные CTA имеют высоту 44 px. Светлая и тёмная темы загружаются до React без CSP-ошибки.

## Ограничения проверки production

Во время аудита `https://212.74.224.226.nip.io` не отвечал: TLS-соединение не устанавливалось, HTTP возвращал пустой ответ. Production не публиковался в рамках этой работы. Повторная проверка нужна после восстановления сервера и отдельной команды на deployment.
