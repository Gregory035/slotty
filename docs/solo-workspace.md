# Личный режим Slotty

## Сценарий

При создании бизнеса владелец выбирает «Работаю один» или «У меня команда». В личном режиме имя аккаунта используется для создания карточки специалиста. Владелец остаётся OWNER, а `CompanyMember.employeeId` связывает его с этой карточкой. Второй аккаунт и отдельная роль EMPLOYEE не нужны.

После создания: услуги → своё расписание → Telegram → тестовая запись. Место приёма можно указать при создании бизнеса. Новые услуги автоматически назначаются владельцу; при создании услуги можно задать перерыв после неё. До настройки рабочих часов доступного времени нет.

В интерфейсе владельца:

- «Сегодня»: записи текущего дня в часовом поясе бизнеса, ближайший незавершённый визит, завершение услуги, неявка, перенос и контакт при наличии телефона/Telegram username клиента.
- Свободное время показывается для выбранной активной услуги с учётом действующих правил доступности. Это не универсальные окна для любой услуги.
- «Мой профиль»: описание, услуги, работы, переход к расписанию и отдельные выходные/отпуск. Форма исключений не перезаписывает недельный график с несколькими интервалами.
- «Моё расписание»: график без выбора сотрудника. Ручная запись тоже не требует повторного выбора самого себя.
- «Участники» скрыты из основного меню. Права на тариф, настройки и другие функции владельца сохраняются. Администратор не получает личный профиль владельца.

Клиент в Mini App: услуга → время → подтверждение. Карточка мастера с описанием, отзывами и каруселью работ доступна отдельной кнопкой. Правила допуска к отзыву и фото не менялись: требуется завершённая услуга, принадлежащая этому клиенту.

## Существующие компании и расширение

Миграция `20261028120000_solo_working_mode` добавляет `Company.workingMode` со значением TEAM по умолчанию. Она не переключает существующие бизнесы и не создаёт им сотрудников.

Владелец включает личный режим в «Настройки → Режим работы». При наличии карточек нужно выбрать свою существующую: так сохраняются записи, график, работы и отзывы. Других активных специалистов и второго владельца быть не должно. Нельзя выбрать карточку другой компании или карточку, связанную с другим пользователем. Параметры существующих назначений услуг, включая перерывы, не перезаписываются.

Добавление специалиста, активация другого специалиста или присоединение второго владельца включает TEAM. Привязка первоначального владельца сохраняется. Можно перейти к команде заранее из настроек. Самостоятельно удалить или отключить свой профиль в SOLO нельзя.

Изменение режима доступно только владельцу через `POST /companies/:companyId/working-mode`. Обычный PATCH компании не принимает `workingMode`. Изменения режима, создание специалиста и автоматическое назначение услуг используют транзакцию и блокировку строки компании, чтобы одновременные запросы не создавали дубли.

## Проверка

Локально, на отдельной тестовой БД, проверены:

- создание владельца с одной учётной записью и одной карточкой;
- сохранение описания, автоматическое назначение услуги и настройка графика;
- путь Mini App до реальной записи в тестовой БД с тестовой Telegram-подписью;
- появление записи у владельца и завершение услуги с экрана «Сегодня»;
- отзыв клиента после завершения визита;
- переход SOLO → TEAM → SOLO без дубля карточки и без потери записи/отзыва;
- мобильная ширина 440×956: лента и действия помещаются, горизонтального скролла нет.

Автоматические проверки прошли: lint, typecheck, 154 unit-теста (110 API + 44 web), 10 интеграционных тестов, production build и восемь существующих браузерных E2E в Chromium desktop и WebKit mobile. Новые интеграционные сценарии находятся в `apps/api/test/solo.integration-spec.ts`. Проверка выполнена 28 октября 2026 года; локальная сборка использовала безопасный режим `SEO_INDEXING_ENABLED=false`.

Проверка ширины и WebKit — не проверка на физическом iPhone/Android и не запуск внутри настоящего Telegram WebView. Отправка сообщений настоящему Telegram-боту в локальном тесте отключена.

## Публикация

Перед запуском обновлённого API применить Prisma migration стандартным release-процессом. Поле добавляется без удаления данных; старый API может работать с расширенной схемой при откате приложения. Не откатывать миграцию удалением поля на работающей базе.

После публикации проверить создание SOLO-бизнеса, `employeeId` владельца, автоматическое назначение услуги, расписание, запись через настоящий Mini App и переключение режимов на отдельном тестовом аккаунте. Сам факт успешной локальной сборки не означает публикацию на сервер.
